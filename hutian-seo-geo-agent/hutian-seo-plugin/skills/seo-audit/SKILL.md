# SEO 审计 — 四步诊断法

使用四步诊断法执行完整的 SEO/GEO 诊断。技术爬取优先使用 `run_diagnosis`
MCP 工具;其余步骤用 `check_schema` 与 `trace_citations` 补充。

## 步骤

### 1. 技术爬取
- 抓取目标 URL;确认 HTTP 200 并跟踪重定向。
- 检查 `robots.txt`(可达、引用了站点地图、无意外屏蔽)。
- 检查 `sitemap.xml`(存在、格式正确、列出目标 URL)。
- 验证 `<title>` 与 meta description 存在且唯一。
- 运行 `run_diagnosis(url)` 工具采集基线信号集。

### 2. 品牌声誉
- 运行 `trace_citations(brand)` 测量生成式引擎如何引用该品牌。
- 记录引用总量、各引擎占比(DeepSeek / GPT / Kimi)、情感倾向与增速。
- 将负面情感或低引用量标记为声誉风险。

### 3. 用户意图
- 确认页面内容与主导搜索意图匹配(信息型 / 商业型 / 交易型)。
- 检查标题层级(单一 H1,合理的 H2/H3)与语义内链。
- 记录页面应排名的查询与实际内容之间的差距。

### 4. 性能体验
- 当设置了 `PAGESPEED_API_KEY` 时,采集 PageSpeed 性能分。
- 标记缓慢的 LCP / 重资源;在相关处推荐压缩与缓存策略。

## 输出

清晰标注以下内容:
- **SEO 评分**(0–100)与 **GEO 评分**(0–100)。
- **实体清晰度** — 通过/未通过及理由(带类型的 JSON-LD、一致的品牌实体)。
- **语义链接** — 内外部实体链接与 `sameAs` 的状态。
- **结构化数据状态** — 发现的 JSON-LD 类型、缺失的推荐字段、校验问题。
- **问题清单** — 按优先级排序,每条配一个具体修复方案。

## 陷阱
- 不要把缺失 PageSpeed 密钥当作失败 —— 它是可选的。
- 一个页面可能 SEO 评分高而 GEO 评分低;两者需独立报告。
- 必须校验 JSON-LD 语法;一个无法解析的块比没有块更糟。

## 验证
修复后重新运行 `run_diagnosis`;确认评分提升且问题清单缩短。
