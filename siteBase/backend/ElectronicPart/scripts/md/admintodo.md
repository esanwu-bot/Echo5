# Admin UI 对比与改进任务 (admintodo)

来源：`docs/admin.html`（产品管理原型） vs 代码库中当前后台管理实现（主要位于 `wine-admin-dashboard/pages/electronic-products/index.js` 与后端 `app/controller/admin/ProductController.php` / `app/controller/api/ProductController.php`）。

目标：列出差异、优先级、并执行若干低风险调整以让当前后台管理更接近原型。部分改动已由自动补丁完成（见下文）。

----

## 概览：原型重点

- 顶栏：搜索框、通知、用户下拉（已在原型 HTML）
- 侧栏：模块分组（仪表盘、产品管理、品牌管理、规格定义、内容管理、系统管理等）
- 主区：产品列表页包含 面包屑、标题、筛选卡片（型号/名称、主分类、子分类、状态）、产品表格（列：产品ID、名称、型号、品牌、分类、库存、状态、操作）与分页
- 产品编辑/创建：新建按钮弹出/跳转，编辑弹窗包含表单（品牌、分类、规格编辑器、价格/库存等）

## 已完成的小改动（由我实现）

- 后端 API `ProductController::brands()` 返回 `SkBrand` 列表（供前端下拉）
- 前端产品页 `wine-admin-dashboard/pages/electronic-products/index.js`：
  - 为编辑模态框添加了 `specs` 编辑支持（Form.List），并在提交时发送规范化的 `specs` 数组（支持 `spec_name`/`spec_value`/`unit`/`sort`）。
  - 将品牌字段改为 `brand_id` 下拉并从 `/api/product/brands` 拉取品牌列表。

这些改动在 repo 中已提交为补丁。

## 差异清单（原型 vs 当前实现）

1. 侧栏与整体布局
   - 原型：完整侧栏、模块层级与默认展开行为。
   - 当前：dashboard frontend 项目部分实现但未完全与原型侧栏一致（部分菜单/子菜单缺失或为静态文档）。
   - 建议：添加或同步侧栏的路由/链接，优先确保 `产品管理 -> 产品列表/分类/品牌/规格` 可访问。

2. 产品筛选卡片
   - 原型：顶部有筛选卡片（型号/名称、主分类、子分类、状态、重置/搜索）。
   - 当前：页面有全局搜索与添加按钮，但缺少可操作的主分类/子分类/状态筛选组件（已为品牌添加下拉）。
   - 建议：在产品页加入筛选卡片并用 `GET /api/products`（或现有产品接口）传参过滤。

3. 规格管理与品牌管理页面
   - 原型：列出“品牌管理 (B)”“规格定义 (B)”子页面。
   - 当前：后端有 `sk_brand` 表并能通过 API 列表获取，但前端缺少专门的管理页面。
   - 建议：先实现品牌管理的最小 CRUD（列表/新增/删除），再实现规格定义管理。

4. 产品表格列与操作
   - 原型：特定列（产品ID/名称/型号/品牌/分类/库存/状态/操作）与操作（编辑/上下架/删除）。
   - 当前：表格列存在但需确认列标题与数据字段一致；编辑模态行为需要回填 `brand_id`、`specs` 等（已做部分实现）。
   - 建议：确认并校准列字段、操作按钮行为，并在编辑后刷新表格以即时反映变化。

5. 导航与路由一致性
   - 原型：使用导航链接跳转到各子页面。
   - 当前：部分页面使用本地 mock API 与静态文件，路由需与后端实际 API 对齐。
   - 建议：同步路由命名（例如 `/admin/products`、`/admin/brands`、`/admin/specs`），并把前端调用调整为对应后端 API 路径。

## 优先任务（短期、可立即执行）

1. (高) 在产品页面添加筛选卡片（主分类/子分类/状态）并把这些条件传给产品列表 API。已开始：前端将从 `/api/product/categories` 或 `/api/product/categories`（若存在）获取分类数据。
2. (高) 在前端继续完善品牌选择（已经从后端拉取品牌并使用 Select），并实现编辑时回填 `brand_id`。
3. (中) 新增一个最小的“品牌管理”页面（列表 + 新增弹窗），用于维护 `sk_brand`（后续可复用到导入/导出）。
4. (中) 列表页的表格列校验与 UX polishing（确保操作按钮行为与提示一致）。
5. (低) 实现“规格定义”页面（列表/新增），并把编辑模态的规格编辑器改为支持选择已有规格定义。

## 风险与注意

- 在生产环境运行数据库迁移（step3）前，请确保所有后端接口与前端字段（brand_id, category_fk_id, spec_id）达成一致，以免写入异常数据。
- 由于前端目前部分为 mock 实现，建议先在测试环境对接真实后端 API 后再进行大规模 UI 改动。
